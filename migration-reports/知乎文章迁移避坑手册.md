# 知乎文章迁移避坑手册

这份文档记录 TinyGrapeLab 从知乎专栏迁移文章时的处理规则，也覆盖中文文章人工翻译为英文页面的流程。后续迁移新文章或整列文章时，优先参考这里，再补充对应的迁移记录。

## 1. 迁移目标

- 文章正文进入 `src/content/notes/<slug>/zh.mdx`。
- 图片放入 `public/media/notes/<slug>/`，正文使用 `/media/notes/<slug>/文件名`。
- 保留知乎原文链接、原始发布日期和更新时间。
- 迁移完成后必须通过 Astro 检查、静态构建和页面内容扫描。
- 不把知乎的编辑说明、转载说明或内部转换信息直接展示在正文中。

## 2. 推荐流程

1. 使用知乎官方 `zhihu_cli` 获取本人文章的完整内容和元数据。
2. 保存原始标题、文章 ID、创建时间、更新时间、正文、图片和视频链接。
3. 转换为 MDX，并先处理公式、代码块、引用块和列表，再进行人工检查。
4. 生成文章目录和 frontmatter。
5. 在浏览器中检查文章顶部、算法段落、图片尺寸、链接和视频区域。
6. 运行检查命令，确认通过后再提交。

迁移脚本：`scripts/migrate-zhihu-column.py`。

## 3. Frontmatter 规则

```yaml
type: note
title: "原始标题"
lang: zh
date: 2019-04-12
updated: 2024-05-18
status: "已发布"
featured: false
priority: 0
tags: [SLAM]
categories: [Spatial AI, 技术笔记]
draft: false
source:
  platform: 知乎
  type: article
  url: https://zhuanlan.zhihu.com/p/<article-id>
```

- `date` 使用知乎 `created` 时间戳转换后的日期。
- `updated` 使用知乎 `updated` 时间戳转换后的日期。
- 同一专栏的文章顺序使用 `priority` 保存，不要依赖文件名或标题排序。
- `priority` 越小越靠前；`0` 表示没有人工排序。
- 置顶文章可以使用负数 priority，同时确认 `src/pages/[lang]/notes/index.astro` 的排序逻辑允许负数。
- 删除文章时，同时删除中文和英文文件，以及不再使用的资源目录。

## 4. 公式转换重点

知乎文章中的公式经常被转换成不完整的 LaTeX。常见问题包括：

- 公式变量丢失，只剩下中文句子或标点。
- `\\begin{array}`、`\\begin{matrix}`、`\\begin{gathered}` 的列数不匹配。
- HTML 实体混入公式，例如 `&lt;`、`&#123;`。
- `\\hfill` 在 KaTeX 中不能正常渲染，可能直接显示为红色文本。
- 公式换行写成普通引用块，导致算法步骤断裂。

处理规则：

- 简单行内公式使用 `$...$`。
- 多行公式使用 `$$...$$`，需要对齐时使用 `aligned`，例如：

```md
$$
\\begin{aligned}
A &= Y_1-Y_2 \\\\
B &= X_2-X_1
\\end{aligned}
$$
```

- 不使用 `\\hfill` 做对齐；用 `aligned` 的 `&` 和 `\\`。
- 矩阵必须检查行列数，每一行使用同样数量的 `&`。
- 算法中的变量不要留在缺失公式的独立段落里，应人工补回并与原文语义核对。

## 5. 算法、代码和引用

- 迁移后的算法步骤优先改成 Markdown 编号列表。
- 有循环、条件分支的算法改成带语言标记的 fenced code block，例如 `text`。
- 不要把算法步骤全部放进连续的 blockquote；知乎转换很容易把公式拆散。
- Swift、Python、C++ 等代码必须保留 fenced code block，并检查缩进和反引号闭合。
- `***TODO***` 会造成视觉层级混乱，改为 `**TODO：...**` 或单独的引用提示。
- 标题不要保留无意义的 `## **标题**` 双重强调，必要时改为普通 Markdown 标题。

## 6. 图片、视频和链接

- 图片路径统一使用本地 `/media/notes/...`，不要依赖知乎图片链接。
- 迁移后检查图片是否过宽；文章正文图片使用统一的内容宽度和圆角样式。
- 知乎视频通常不能稳定直接嵌入，可保留原链接；Bilibili 视频使用明确的嵌入组件和 BV 号。
- 删除知乎原文编辑信息、迁移说明和不需要展示的作者署名。
- 链接文字应有高亮颜色；检查 Markdown 链接是否被转换成断裂的裸 URL。
- 特别注意 URL 中的 `&`、反斜杠和 HTML 实体，避免链接被拼接或截断。

## 7. 验证清单

```sh
npm run check
npm run build
```

构建后至少扫描：

```sh
rg -l 'katex-error' dist/zh dist/en
rg -l 'hfill|&#123;|&#125;' dist/zh dist/en
```

结果要求：

- `npm run check` 为 0 errors、0 warnings、0 hints。
- `npm run build` 成功完成，页面数量符合当前内容数量。
- `katex-error` 为 0。
- 不出现可见的 `\\hfill`、HTML 实体或未转换的公式命令。
- 中文和英文页面都能打开，文章列表顺序符合预期。
- 重点人工查看：文章标题、第一屏、公式密集段、算法段、代码段、图片和视频。

## 8. 迁移记录

每次迁移单篇文章或一批文章，都在 `migration-reports/` 创建记录，至少包含：

- 原文 URL 和文章 ID。
- 迁移日期。
- 使用的获取方式。
- 新增或删除的文章路径。
- 图片、视频、公式的特殊处理。
- 已执行的验证命令和遗留问题。

## 9. 中文到英文页面转换

### 目标和原则

- 每篇中文文章都要有同 slug 的英文文件，例如 src/content/notes/slug/en.mdx。
- 翻译正文、标题、图片替代文本、说明和 frontmatter；保留公式、代码、图片、视频、外部链接和原文日期。
- 英文页不是摘要。原文的算法推导、公式编号、代码块、实验图、下载链接和参考资料都必须保留。
- 英文 date、updated、priority、featured、source 和关联内容必须与中文页一致。

### 推荐步骤

1. 逐段阅读中文原稿，先列出标题层级、公式块、代码块、图片和视频链接。
2. 新建英文文件，复制并翻译 frontmatter；不要手改日期或排序。
3. 人工翻译正文。技术术语保持全站一致，例如 SLAM、VIO、ESKF、Bundle Adjustment 和 reprojection error。
4. 公式优先重写为 KaTeX 兼容形式，不能直接照搬知乎导出的残缺 LaTeX。
5. 保留代码逻辑和代码块；代码注释可翻译，但不要改动可执行语义。
6. 图片继续引用同一条本地 /media/notes/slug/ 路径；链接使用 Markdown 语法。
7. 同时完成中文和英文页的分类字段，避免两个语言版本在筛选页落入不同分类。

### MDX 和 KaTeX 特别规则

- MDX 中裸的尖括号 URL 会被当成 JSX 标签而构建失败，必须写成标准 Markdown 链接。
- 不要在 JavaScript 模板字符串里直接写 LaTeX 的美元符号加花括号；会触发模板插值。使用等价记法或转义。
- 显示公式内不要在最外层使用孤立换行命令；多行对齐用 aligned、bmatrix 等环境。
- 不使用 HTML 实体，不使用可见的 hfill 命令。
- 不要把中文解释文字混入数学模式；矩阵的列数必须和 array 声明一致。

### 英文页验证

~~~sh
npm run check
npm run build
rg -l 'katex-error' dist/en/notes
~~~

通过标准：

- astro check 为 0 errors、0 warnings、0 hints。
- 构建成功，新增英文路由出现在构建输出中。
- 新增英文页面没有 katex-error。
- 至少人工抽查首屏、公式密集段、代码段、图片、视频和内部链接。

## 10. 文章分类规范

笔记页使用 categories 的第一项作为主分类，第二项保留内容类型。

| 中文 | English | 使用范围 |
| --- | --- | --- |
| SLAM | SLAM | 视觉/激光/惯导定位、建图、优化、几何、传感器融合 |
| PhoneAI | Phone AI | 手机采集、传感器、端侧智能、相关产品工作流 |
| 航空 | Aviation | 航拍、飞行器、稳拍、航空视觉 |
| AI | AI | 智能体、模型、AI 工具和相关研究 |
| 工程 | Engineering | C++、系统、工具链、通用工程实现 |

示例：

~~~yaml
tags: [SLAM, VIO, Sensor Fusion]
categories: [SLAM, Technical Notes]
~~~

- 主分类用于文章列表筛选，必须在中英文文件中成对更新。
- tags 用于描述具体技术点，可以保留多个；不要再给所有文章套同一组泛标签。
